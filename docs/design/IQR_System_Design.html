IQR — Intelligent Quality Review for SOX 404 Controls

A compiled-plan agentic platform that validates SOX 404 control evidence packages end-to-end: agents reason, deterministic tools compute, and a frozen SME-approved plan governs every run. Model-agnostic by construction — Claude in the lab, DaVinci in production.

01Why this shape of Agentic AI

Most "AI for controls testing" fails review for one reason: the model both finds the number and judges the number, so nobody can replay why a control passed. IQR splits those roles permanently:

  • Plans govern. What gets checked is compiled once per control from the SOX 404 document, reviewed by an SME, then frozen and versioned. The runtime executes the plan; it never improvises scope.
  • Tools compute. Every number, timestamp, and email fact comes from a deterministic tool (cell_read, recompute, timestamp, email_parse, ocr_read) that returns a citation to the exact cell or line. Numeric checks touch no model at all — an invariant test asserts the model-call counter stays at zero.
  • Agents reason. Where judgment is needed — which screenshot ties to which cell, whether approval language is an approval — a tool-using agent decides, and every tool call it makes lands in the run ledger.

The result a reviewer sees is not "the AI said pass." It is: delta recomputed as 8.28e-06 against tolerance 0.01 from Recon!B30339; approval parsed from message line 1; preparer ≠ approver per Summary!D14 vs the sender header. Every claim carries its evidence address.

02System architecture

IQR has two phases with different trust models. Design time uses the LLM freely — its output is reviewed by a human before it can ever govern a run. Run time is deterministic-first — the LLM only reasons inside tool-using agents whose every step is logged.

Runtime stack
Python 3.12 · LangGraph · openpyxl / pyxlsb / extract-msg / python-docx · Tesseract OCR · FastAPI console on 127.0.0.1
Storage
Content-addressed evidence store (SHA-256 named blobs, immutable) · versioned plan store · append-only JSONL run ledgers
Model seat
Single adapter interface; backend chosen by environment (stub · Claude · DaVinci) — see §03

03The model seat & DaVinci

The platform does not depend on any specific LLM vendor. One adapter (iqr/agents/model_client.py) exposes complete(system, prompt) → JSON, and the concrete backend is picked by environment variables at startup:

  • The POC you demo runs with zero external calls — the stub answers every agent decision deterministically, which is why the whole eval suite runs on an air-gapped machine.
  • On the HP machine, only the endpoint URL and key change. No code change: set MODEL_NAME=davinci plus the endpoint in .env. The fallback chain means a model outage degrades to stub behavior instead of blocking the close calendar.
  • The ledger records which backend answered every call, so a run is attributable to its model version — an audit requirement, not a nicety.
Key claim for stakeholders: the LLM is consulted in exactly two places — compiling draft plans (human-reviewed before use) and reasoning inside logged, tool-using check agents. All arithmetic, all extraction, and all verdict mechanics are deterministic Python that runs identically with any backend, including none.

04Evidence ingestion

Real GRC packages are nested: an Outlook .msg containing a ZIP containing macro workbooks; a 404 Word document with a 184 MB Excel workbook embedded as an OLE object; binary .xlsb workbooks; screenshots inside everything. The ingester walks all of it:

  • Content-addressed store: every leaf is SHA-256 hashed and stored immutably; re-ingesting identical bytes is a no-op and citations are stable by construction.
  • Format coverage: .xlsx/.xlsm (values + formulas + embedded images), .xlsb, .docx (paragraphs + embedded images + OLE embeddings), .msg and .eml (headers, body lines, attachments), images (OCR).
  • Big-file streaming: files over 50 MB are hashed and stored in chunks and their containers walked from disk; workbooks over 60 MB stream values in read-only mode with an explicit truncation sentinel rather than a silent cap.
  • Honest errors: unreadable artifacts become recorded errors on the graph (e.g. a SharePoint link placeholder posing as an attachment), never silent skips.

05Check execution workflow

Every run executes the same frozen LangGraph topology — the topology itself is versioned and hash-signed so releases can diff it:

Check typeWho computesExample (real, control 10032)
numericPure Python — model-free, invariant-tested BPC grand total vs ODW grand total within 0.01 (Recon!B30339 vs G53656)
temporalAgent + timestamp tool Approval postdates certified WEBI run — 8:29 PM GMT (Summary!D13) vs email header date
signoffAgent + email_parse tool SoD: preparer Summary!D14 ≠ approver (.msg sender); approval language on line 1
visionAgent + ocr_read tool Screenshot provenance: "SAP BI Launch Pad", certified host, report name

Missing required evidence becomes a GAP, never a silent pass. Artifacts present but not expected become observations — except items the SME excluded in the plan (e.g. tabs annotated "not part of SOX control"), which are respected as out of scope.

07Governance & auditability

  • Frozen plans: approving a plan writes an immutable versioned file; re-approving the same version is an error. Runtime refuses unapproved plans.
  • Run ledger: every run appends JSONL events — topology hash, model identity, every tool call with args and results, every agent conclusion, the adjudication. python -m iqr.cli explain <run_id> replays the entire decision trace.
  • Eval gates: a fixture harness with five gate metrics (false-pass rate zero, citation coverage, gap detection, scope respect, determinism) must pass before any plan or code change ships. The POC suite is 36 tests, all green.
  • Audit pack: each run assembles verdict + findings + citations + evidence hashes into a reviewable pack.

08Step-by-step HP deployment

Sequenced so every batch has a hard gate before the next. Nothing needs admin rights; nothing calls outside the machine except the approved DaVinci endpoint.

  1. Pre-flight ~30 min

    Verify python --version ≥ 3.12 (python.org user install via IT self-service if absent). Check proxy (netsh winhttp show proxy). Canary pip install requests; if corporate SSL interception blocks it: pip config set global.cert <HP-CA-bundle.pem>. Confirm DaVinci endpoint URL + key issuance.

  2. Install + offline smoke ~1 hr · zero keys

    git clone <repo> && cd IQR
python -m venv .venv && .venv/bin/pip install -e .
# Tesseract: UB-Mannheim installer to %LOCALAPPDATA% (no admin)
.venv/bin/pytest -q            # gate: 36/36
.venv/bin/python -m iqr.cli eval   # gate: all five metrics green

    This proves the machine before any real data or key touches it.

  3. Keys + model chain ~30 min

    cp .env.example .env    # add DaVinci URL + key, MODEL_NAME=davinci
python -m iqr.cli testmodel   # ledger records which backend answered

  4. Real-corpus rehearsal half a day

    Drop one real GRC package into data/input/; run the ingestion probes in tests/real/. Gate: every leaf hashed, nesting walked, errors empty or explained. This exact rehearsal has already been performed — expected outputs are in docs/REAL_VALIDATION.md.

  5. Plan compilation + SME freeze ~1 hr per control

    python -m iqr.cli compile <404.docx> C10032 monthly
# SME reviews draft JSON: pins timestamp anchors + timezones,
# tolerances, scope exclusions, authoritative artifacts
python -m iqr.cli approve C10032 "<sme name>"

    Order: 10032 → 23024 → 10075.

  6. Shadow cycle one close period

    Run python -m iqr.cli run <control> <package> beside the human reviewer each close. Compare verdicts; disagreements feed the exception queue and refine plans (version bump + re-approval). Gate: eval metrics on real packages decide graduation to Assist mode.

  7. Productionize

    Service-ify via Task Scheduler / nssm; move data/ to a backed-up local drive (never a cloud-synced folder); add the SharePoint/mailbox connector behind the existing resolver interface; stand up Golden Library governance — eval gate + SME sign-off before any plan ships.

09IT & security posture

Network
Console binds 127.0.0.1 only; no inbound ports; outbound traffic only to the approved DaVinci endpoint. Offline mode makes zero network calls.
Telemetry
None. No analytics, no phone-home. (This is why the console is FastAPI + static HTML rather than Streamlit.)
Dependencies
Mainstream, auditable Python packages: LangGraph, openpyxl, pyxlsb, extract-msg, python-docx, pytesseract, FastAPI, pydantic.
Data at rest
Evidence blobs and ledgers stay on the local machine under data/; nothing is uploaded anywhere.
Privilege
User-mode installs only; no admin rights at any step.

10Roadmap

  • Parsed-artifact cache (hash-keyed) so repeat runs skip re-extraction.
  • SharePoint / mailbox connector — 10075's chain references SharePoint-hosted files; fetch them through the resolver with the same hashing custody.
  • PDF ingestion (pypdf + OCR fallback) for image-only GRC artifacts.
  • Vision-model tie-outs where DaVinci's multimodal endpoint can read screenshot tables OCR cannot — held behind the same tool-citation contract.
  • Golden Library of approved plans across the SOX program, governed by the eval gate.
